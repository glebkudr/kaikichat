# Native runtime permissions panel

Add explicit Tauri commands provision_runtime/list_runtimes/revoke_runtime to the local main-window ACL, using the existing owner bridge. Renderer cannot call the unrestricted grant_runtime or choose seed/path/command. Native test checks actual daemon provisioning/retry/list/revoke, private credentials path, absence of seed in public results, and denial of foreign-origin/secondary-window actions with unchanged registry.

The "Agents" panel shows current grant name, selected dialogs, reading/sending rights, expiration and active/expired/revoked status. The owner chooses a name and at least one dialog; read access is explicit in the form explanation, sending is opt-in, lifetime choices are finite, data limit is bounded. Each new setup generates agent/service IDs and an operation ID. On failure an unchanged retry preserves the entire approved request (IDs, scope, expiration); an edited form creates a new operation. Show errors and reload the real registry even if credentials materialization fails.

Successful provisioning displays the exact returned MCP client config in a readonly textarea, with no secret key. Revoke targets the exact grant ID; failed revoke leaves status active. Returning to chat preserves the message draft. No fictitious running/online agent status: a grant is permission, not a live LLM process. UI types/API/component tests precede implementation; headless screenshots must be inspected. Packaged E2E must later create this grant through visible UI controls in hidden WKWebView, launch bundled MCP from displayed config, send/poll/ack with a real peer and verify UI revocation denies the same running MCP client. Full V1 remains open.
