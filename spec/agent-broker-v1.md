# Shared agent broker: first integrated messaging gate

Build on capabilities without exposing the owner IPC token to an MCP process. Owner-authenticated registration signs a finite root grant for one runtime public key, stable agent/service IDs and explicitly selected existing conversations. Initial broker registration supports only inbox.read/messages.send; paid actions, delegated registration and other service commands are enabled with their real implementations in later gates. It must reject unsupported actions rather than imply a working payment engine. Default ownership epoch0, device/service epoch1; current records/revocations are encrypted state owned by the daemon.

Owner-facing `grant_runtime(RuntimeGrantRequest, now)` receives name, principal public key, agent_id, service_id, conversation_ids, actions, expires_at and max_data_bytes. It derives recipient roots and exact `conversation:<id>` resources from actual contacts, creates the signed GrantClaims with finite TTL, budget0, depth0, no_subcontract and returns public `RuntimeGrant { grant_id, wire }`. Duplicate active principal registration is an explicit error. Revocation persists before success and affects every later call, including exact operation retries.

Agent proof is SignedDocument Kind Identity, body subtype3: definite CBOR `[3, grant_id32, method, canonical_request_json_bytes, nonce32]`. `AgentCall::draft(domain, ownership_epoch, now)` gives a30-second expiry. Recursively sorted JSON object keys; unknown typed command fields are rejected. Subject signs with its runtime key; the server never accepts a caller-supplied principal or AuthContext. Exact grant ID, signature, domain, epoch, active time and current registration must match. Replay key is grant+nonce; successful reads/mutations consume it durably, failures consume no authority state. Expired replay entries can be pruned after their proof cannot be accepted; bound the active window and deny overflow. No owner/root/sign/shell/wallet method exists in the agent dispatcher.

`AppCore::agent_call(proof_wire, now)` derives the context from current registry state and verifies GrantChain on every call. `snapshot` returns agentId/serviceId and only conversations readable by that grant; it does not expose the owner's profile or other dialogs. `send_message` derives recipient/resource and UTF-8 byte count from the actual conversation and text, checks the grant, namespaces idempotency by authenticated runtime and reuses the existing send reducer/OpenMLS/outbox/receipt path. No fabricated delivery or postage is introduced.

Grant fence, replay journal and authorization operation binding must be committed in the same SQL transaction as new MLS/history/outbox state. Exact operation retry with a fresh signed nonce returns the original message and consumes that fresh nonce, without advancing MLS or duplicating work. If needed, extend ProfileStore's existing outgoing commit with a separate explicit set of states applied only on a matching committed retry (never apply newly prepared MLS state on retry). SQL fault at an authorization write rolls back the complete new send; the same proof may then safely retry. Owner commands remain available via the authenticated owner boundary; agent proof can never select the owner branch.

This core gate precedes adding the proof variant to local IPC and the official rmcp3.2.0 stdio adapter. End-to-end acceptance additionally requires real two-daemon calls, modern2026-07-28 discovery and legacy initialize, cancellation/disconnect behavior, durable paginated inbox leases/acks and native permission management. None is declared implemented by this spec.

Initial bounds: at most1024 retained runtime registrations and4096 active replay entries per profile; overflow fails closed. max_data_bytes currently bounds UTF-8 content of outbound messages. Scoped snapshot retains the existing history window (1000 records per conversation); paginated inbox with byte-limited responses is a separate required gate. Snapshot reads cannot be used by send-only grants. Reissuing an identical revoked signed grant never resurrects it.
