# I02: signed grants and atomic budget foundation

The shared broker authenticates a principal before building a trusted authorization context. Grant verification never promotes caller-supplied identity, epochs, revocation lists, price or data size into trusted facts. This module provides signed delegation validation and prepared SQL state changes; daemon/MCP/UI adapters must use it with the same application transaction. It is not yet a completed broker or MCP server.

Grant wire reuses the existing canonical SignedDocument and Ed25519 implementation. Kind Identity, mandatory expiry, ownership epoch in the envelope. Identity body subtype 1 is the existing NodeRecord; subtype 2 is DelegationGrant. Definite CBOR array of 16 fields (wire version 3; version 2 carried a job depth and is no longer accepted):

`[3, owner_key32, agent_id32, service_id32, subject_key32, parent_document_id32_or_null, device_epoch, service_epoch, actions_sorted_uint_array, resources_sorted_text_array, recipients_sorted_text_array, budget_asset, budget_units, max_data_bytes, remaining_delegation_depth, no_subcontract_bool]`.

Actions: 1 inbox.read, 2 messages.send, 3 groups.create, 4 groups.manage, 7 artifacts.read, 8 artifacts.write, 9 reviews.publish, 10 reviews.amend, 11 reviews.withdraw, 12 reviews.reply, 13 postage.spend. Codes 5, 6 and 14 (agent orders) are retired and fail closed. There is no root-sign/export-secrets/shell/owner action. Unknown actions fail closed. Scope identifiers are exact bounded strings, with no wildcard semantics; empty sets grant no access.

Limits: grant wire <=16KiB, chain 1..5, actions <=11, resources and recipients <=32 each, identifier 1..160 UTF-8 bytes and no control/wildcard characters, asset1..96, positive finite lifetime <=30days, delegation depth<=4. Mandatory expiry; even a grant issued within generic wire clock tolerance is denied before its actual issued_at. Decode must be canonical including sorted unique sets and reject trailing data/unknown fields.

Root grant must be signed by the trusted current owner and have no parent. Every child must reference the exact parent document hash and be signed by the parent's subject. Owner/agent/service/ownership epoch/service epoch remain bound. Each subject's device epoch must match the broker's current epoch map. Leaf subject must equal the authenticated caller. Revocation of any ancestor denies the chain. Child permissions/resources/recipients are subsets, asset identical, budget/data limits do not increase, expiry does not extend, issued_at is not before parent, delegation depth strictly decreases, no_subcontract cannot be relaxed.

ScopeRequest has action, exact resource, optional recipient, integer units with asset, data_bytes and subcontract flag. All applicable restrictions are checked. A recipient is mandatory for messages.send and postage.spend; omission is allowed for local reads and resource actions without a target, and any supplied recipient must be in the grant. Read/publish/reply rights remain independent; knowing a grant does not make the caller its subject. Financial debits require the explicit postage.spend action. Other action checks carry zero units, so a send permission alone cannot be reinterpreted as spending authority.

The future broker must obtain epochs/revocations from its own current state on every request and fence concurrent authority changes in the same action transaction; a cached verified chain is not an authorization session. This pure module does not implement that registry or trust caller-supplied maps. Price/size/subcontract metadata must be derived from the validated action by the broker, not forwarded unchecked from MCP.

Budget reservations share the existing encrypted ProfileStore. `prepare_debit(store, chain, operation_id, request)` returns StateChange entries for every ancestor counter and an operation binding, without committing them. The broker adds these entries to the SAME atomic transaction as durable action/outbox/crypto changes. Identical committed retries return already_committed with no state changes; changed action/amount/resource under the same principal operation ID conflicts. Every ancestor is charged, so sibling runtimes cannot create fresh parent budget. Integer overflow, changed asset, stale CAS, SQL failure and mismatched profile identity fail closed. A prepared reservation discarded before commit spends nothing. No external payment, mint, escrow or economic strategy is implemented here.

Validation includes independently assembled CBOR grant wire, ordinary attenuation and role separation, attempts to expand one bound, wrong caller/root/network/epochs/revocation/time, and real SQLCipher transactions for shared sibling budgets, competing prepared calls, restart/idempotency and rollback alongside a business state write.
