# Durable scoped agent inbox

Signed broker commands inbox_poll and inbox_ack require ReadInbox on the existing selected conversation; send-only grants and foreign conversations fail. Poll takes conversationId, operationId (1..128 printable exact identifier), limit1..100, maxBytes1..48000 and leaseSeconds1..600 (long enough for a reasoning agent to handle the page). The actual UTF-8 text sum never exceeds maxBytes or the grant max_data_bytes. Too-small first-item capacity fails without consuming state; text is never truncated. Pagination scans at most1000 stored records per call, filtering owner-authored records and non-text events. A scan-only page may require ack to advance past skipped records. hasMore is conservative when the scan boundary is reached.

An inbox cursor and at most one active lease are shared by (agentId, serviceId, conversationId), across its runtimes. Poll returns {conversationId,items:[{id,author,text,createdAt,sequence}],cursor,leaseId,expiresAt,hasMore}. With nothing scanned beyond acknowledged cursor it returns an empty page with null leaseId/expiresAt. A nonempty scanned range has a random lease bound to grant/principal and finite expiry. A different poll operation cannot replace a live lease. After expiry another runtime can lease the same unacknowledged messages. Current grant verification always precedes read/retry/ack.

Poll idempotency binds the authenticated principal, grant and exact typed request. Fresh-proof same-operation retry returns the original page (including original expiry) after restart and after ack; changed request conflicts. Use a new operation ID for a new poll. Poll itself never advances the acknowledged cursor. Ack takes conversationId and leaseId, verifies the creating grant/principal and unexpired current lease, advances the cursor once and clears that lease. An exact already-committed ack remains idempotent and cannot clear a newer lease; an expired/replaced unacknowledged lease cannot ack. Revoked principals cannot read or acknowledge outstanding work.

Persist cursors, leases and poll/ack operation results under authorization/inbox/* in SQLCipher. Broker registry fence and fresh proof nonce commit atomically with every successful transition/retry. SQL fault rolls back all of them and the same proof can retry. Neither poll nor ack changes MLS/history/outbox or the owner's UI read state. This module prepares MCP inbox.poll/inbox.ack; it does not claim runtime wake-up, jobs or subscription delivery.
