# N02: optional local peer discovery

Status: complete local native/release and Linux network gates PASS on 2026-09-05. This implements IPv4 LAN discovery and its native controls. Full N02/registry, native LAN platform acceptance and V1 remain open.

## Contract and implementation

The owner opts into mDNS using «Find nodes on the local network», or `serve --lan-discovery` when no saved owner preferences exist. `lanDiscovery` is an optional input/legacy field with default false, always present in new output. Saving changes the daemon through the existing encrypted CAS/replacement-swarm path. Same-value retries do not reconnect. Saved preferences override CLI defaults. `relayOnly` suppresses mDNS even when the saved LAN preference is true; the UI explains this state.

`crates/node/src/lan.rs` wraps the existing libp2p mDNS implementation. It exposes up to32 unverified peer hints, four routes per peer, with each announcement expiring after60seconds without refresh. Own peer, mismatched PeerID, loopback/wildcard/multicast, DNS and relay advertisements are rejected. IPv4 packets use the standard `_p2p._udp.local` service. The backend never promotes raw announcements into contact/root authority.

The wrapper does not contribute unverified addresses through `handle_pending_outbound_connection` or `NewExternalAddrOfPeer`. Its hints instead join the shared bootstrap scheduler: up to4 explicit hints,64 signed cache records and32 LAN peers, bounded at100 candidates; four requests in flight, existing backoff and eight addresses per candidate. A LAN address update keeps an existing cached expected root. Actual session PeerID and signed network/root/record validation remain in the shared bootstrap admission path. Imported contacts, messages and agent scope are separate operations.

The wrapper expires upstream discovered entries after copying accepted hints to its bounded state and processes at most16 upstream events per poll. It uses the supported but deprecated `expire_node` API from pinned libp2p-mdns0.48.0; this must be revisited when upgrading. These checks bound retained application hints; they do not constitute a complete proof of upstream parser/interface-queue memory under a sustained hostile multicast flood.

Dependency verification before enabling the feature: the [official crates index](https://index.crates.io/li/bp/libp2p-mdns) reports0.48.0 as the newest non-yanked release, compatible with libp2p0.56 and Rust1.83+. The existing lock already contained this resolution; its mDNS feature is now compiled. The compatible hickory-proto0.25.2 resolves through that crate. DNS fixture encoding follows the [published libp2p mDNS specification](https://github.com/libp2p/specs/blob/master/discovery/mdns.md).
