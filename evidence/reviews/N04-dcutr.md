Tests first: scripts/check-network.mjs adds two actual Linux NAT scenarios using the same owned topology/IPC/MLS/receipt helpers. The success case starts clients on separate private LANs behind stateful MASQUERADE routers and a single QUIC relay. Independent unsolicited public UDP probes and private-IP probes hit real DROP rules; relay observations prove translated client addresses. After the first encrypted message, both clients must obtain a real direct QUIC connection to the other's public NAT mapping and at least one actual DCUtR success event. The only relay is then stopped; only the direct peer connection may remain, and real messages/replies/receipts must continue in both directions with exact histories and zero outbox.

The failure case additionally blocks peer WAN UDP, expects an actual failed upgrade plus nonzero packet DROP counters, and verifies that the surviving relay connection still delivers the reply/receipt. Existing relay-only mode tests must continue proving no direct application connection. No test fixture opens client peer mappings or forwards incoming ports. Python supplies only process/IPC/router setup and one-way negative UDP probes.

Proposed production boundary: current libp2p Identify + DCUtR behavior with finite swarm limits, automatic upgrades disabled in explicit relay-only mode, finite owner diagnostic counters. Identify address observations are candidates, not confirmed external addresses or application root binding. Unsigned Identify address cache must not add dial routes to the application; signed NodeRecord verification remains authoritative. AutoNAT reachability, TCP hole punching and desktop NAT acceptance remain separate open work.
