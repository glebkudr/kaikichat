# N04 Linux direct + restrictive NAT/relay verification

New executable E2E validates current production networking on Linux: it is not itself a new transport implementation. AutoNAT/DCUtR/hole punching and native desktop NAT acceptance remain open. Do not call the complete NAT matrix or N04 finished after these two cases pass.

Test contract: build current Rust sources into a Linux image (source fingerprint rejects stale images), direct control between two networked daemons with actual MLS messages/replies/receipts; then two separate private networks, their own NAT routers with default routes and conntrack-based inbound filtering, two relay providers over TCP/QUIC. TCP probes between clients must fail and increment explicit router drop counters; masquerade counters must grow and both relays must observe each client's translated router address. Actual contact/MLS/message/reply/receipt flow must then work. Kill the sole active application circuit provider, deliver through the independent survivor, kill both, queue, restart sender, restore survivor and receive the original operation/receipt without a repeated send. Verify exact histories and empty sender outbox.

Tests use real Docker networks, Linux iptables/conntrack, compiled Rust daemon, private SQLCipher state and random bootstrap secrets created only inside each container. Python fixture is only test process/IPC/network setup; it never implements messaging, cryptography or receipt behavior. Source hash includes all copied Rust files and fixture files. BuildKit caches have dedicated ain-nat IDs; host build target is not mounted.

All containers/networks have per-run names and labels. Creation attempts are registered by unique name before invoking Docker; cleanup inspects the current resource, verifies its run label and removes its resolved ID. Missing resources are harmless. SIGINT/SIGTERM stop subsequent work and enter common cleanup after the current bounded Docker command returns; builds can be terminated before any test networks exist. A current passed:false report invalidates any previous success before work begins. It never changes host firewall, host routes or other projects. No production/public service deployment. Normal app remains ad-hoc signed macOS release until supported-platform gates are complete.
