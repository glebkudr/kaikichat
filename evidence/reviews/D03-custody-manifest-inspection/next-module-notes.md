## Existing implementation seams examined during final regression

- `crates/node/src/custody_sync.rs` is the existing bounded recipient scheduler (four work items, round robin, original shared slots, admission/backoff, durable Core bookmarks). Reuse its runtime cadence and transport guards, not its private mailbox capability for holder maintenance.
- `crates/node/src/custody_copy.rs` already verifies/retains both copy sides, preserves the full original payment and flat origin, and uses the shared queue. Autonomous work should call the same implementation instead of creating another wire/verification path.
- `crates/postage-spend/src/custody/inspection.rs` provides real holder freshness and an authenticated local receipt view. Current freshness is at most 30 seconds. Signed receipt count and distinct transport count remain separate from observed availability.
- `crates/core/src/custodian_publication.rs` only answers the current checkpoint. `custody_copy_operator.rs` uses `l2/operator-proof/{index}` and requires its stored epoch to match the original snapshot. `operator_publication.rs::publish_operator_proof` replaces that record, so merely adding a scheduler would not solve historical discovery. Preserve bounded authenticated historical own membership material before replacing publication; any pruning horizon must cover maximum still-live obligation lifetime and cannot silently revive permission.
- `PrivateCustodyPlacement` already derives the finite primary/replacement ordinals. No second sampler or sender-selected placement is needed.
- Incoming custody is bounded to 128 objects/8 MiB in the actual node. Durable work enumeration, atomic attempt reservations and expiry cleanup should reuse those limits. A failed persistence operation must emit no new outbound work. Shared queue capacity remains physical until stream completion, including draining/cancelled work.

Candidate test groups before implementation: actual 1→10 and 10→7→10 process scenario with both clients absent and read-only observer; surviving-holder restart and source loss; partition/heal without duplicate spend or extended expiry; unavailable/lying holder and failed replacement; finite candidate/bandwidth/backoff bounds; historical membership publication replacement; per-operator revoke and scoped-agent denial; SQL failure before dispatch and after remote acceptance; explicit degraded reason when finite eligible replacements are insufficient. Do not equate several operator units on one transport with independent copies or turn missing probes into punitive evidence.
