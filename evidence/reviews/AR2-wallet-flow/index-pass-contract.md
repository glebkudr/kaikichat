# Index preparation scheduling fix

Two unchanged ordinary paid native lifecycle runs (published-graph C3/C4) hit the existing five-second public_sender_status IPC deadline during cold sender completion. C5 diagnostic replay passed but recorded reads nearly five seconds; macOS sample stacks show request_custody_index_location/outgoing_index_locations/save_outgoing JSON serialization inside the synchronous index publisher. No whole latency guarantee is established by the proposed fix.

Current publisher issues up to four expensive successful requests without checking its 20ms budget; only failed requests check elapsed time. Extract its existing scheduling loop into Stage::publish(transfers, completed, now, prepare) so successful AND failed attempts yield once the budget is spent. Production supplies Instant::now and its unchanged real peer lookup/paid request preparation. The callback returns Reply<Attempt>, with Attempt::{Unavailable, Queued(String), Rejected(&static str)}. Outer fatal errors propagate unchanged; request rejections retain the existing backoff/capacity behavior. Stage::publish returns Reply<Option<&static str>>, carrying the last nonfatal request error for Work.error. This boundary only schedules opaque request IDs; it cannot grant paid admission, ACKs, Core completion, or history coverage. Keep four actual attempts maximum, rotation past failures/successes, five-second peer-specific retry delay, skip pending/completed positions, and capacity halt behavior. No test-only crypto, deadline inflation, lower replica target or bypassed durable validation.

Tests exercise this actual Stage scheduler with a deterministic elapsed-time source and opaque queued requests. Five tests cover expensive successful work yielding and eventually scheduling all ten positions with no pending/completed duplicates; fast four-request passes and reconnect; expensive failures with peer-specific backoff, all nine other positions, capacity refusal and successful retry; capacity halt with other eligible positions; fast failures counting toward cap4, rotation and backoff; outer fatal propagation without pending or later callbacks. They are explicitly not paid transport tests. Existing actual paid native workflow remains the integration gate after the fix. The missing Stage::publish API is the expected preproduction compile RED. Only cfg(test) wiring was added in the production file before review; production implementation remains unchanged.
