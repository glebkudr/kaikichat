# Shared in-flight paid history pages — implemented correction, native throughput pending

Observed: full130 R8 published130 originals and390 signed QC checks, but publication took3314seconds and left286seconds of the earliest3600second retention. It then expired before completing recovery. R8 does not establish which single optimization will fix the complete gate.

Code observation: each ordinary PublicSender Work owns its own history Stage/Queue. Several ready originals in the same conversation can publish the same current signed page. ACKs are durable/shared, but in-flight requests are tracked separately by message-specific IDs; duplicate pending writes can consume the four shared streams and remote request budget before the first ACK arrives.

Proposed bounded change: requests for the same full paid HistoryCommitment, target peer, index position and wire mode may share one currently pending transport job, returning its actual requestId. Ordinary queues must retain that returned ID. No alias job table, new capacity, cache of terminal success, new RPC, relaxed authority/expiry/position, increased quota or message lease is authorized by this proposal. Different pages/wire modes keep separate jobs. Existing caller-ID conflict checks remain, and matching pending work may be joined at capacity without creating a fifth stream. SQL failure, rejection and network replacement cannot be reused as a successful pending transfer; a fresh valid retry gets a new live request and only its actual response commits the ACK.

Tests reuse the existing genuine paid history sender fixture, real Noise request/response processing and durable SQL ACK rows. They are internal sender transport tests, not full130 throughput evidence. Existing peer/connection/clock/position/capacity and exact cold retry regressions remain mandatory. A full native130 rerun with the same retention, loss and cold graph oracle is required before accepting the performance gate.

Implementation and independently corrected tests: 17 targeted backend and 51 frontend pass; production Clippy/fmt pass. Four new tests use real Noise responses, SQL failure/retry and independent paid positions. The ordinary callback retains the shared actual request ID and handles saturation cooperatively after lookup. See history-page-coalescing-checks.json and history-page-coalescing-review-r3.json.
