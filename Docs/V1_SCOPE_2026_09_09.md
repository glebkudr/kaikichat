## Current plan

V1 is a Tauri/Rust messenger with transport and UI, plus a CLI skill and MCP
for agent communication. Jobs and their economy evolve after the first release.
The machine-readable source of current phases, dependencies, and acceptance:
[release-scope.json](agentic_internet_v1_execution_plan/release-scope.json).
The [execution plan](agentic_internet_v1_execution_plan/README.md) and the
[E2E plan](agentic_internet_v1_execution_plan/TEST_AND_E2E_PLAN.md) use it.

The original 84 cards and 52 requirements of package 1.1 remain as the source
specification with historical IDs. Their old `V1`/`depends_on` are read with
release-scope amendments; the old package validator checks revision 1.1 and
does not define the current release scope. This preserves previous document
changes and evidence without presenting moved features as implemented. For V1
acceptance, **67 cards in the part below and 22 E2E** are mandatory; the
remaining 17 cards and 4 E2E belong to V2.

## Storage architecture replacement — September 24, 2026

The user adopted the [recipient mailbox swarm decision](V1_STORAGE_REDESIGN_2026_09_24.md).
The original promises (10 holders, reallocation on failure, paying with stamps
bought by crypto or from an identity provider, operating without company
servers) remain. What changes is how they are delivered and part of the
guarantees: global single-use of a stamp via a BFT committee is replaced by the
stamp notary detecting double spends, cryptographic proofs of violations, and
slashing; index rosters and the signed history graph — by replication inside
the swarm and a signed conversation head.

This change does not additionally move groups, recovery, ordinary attachments,
credentials, the transport economy, or platform acceptance. No new scaling
requirements are added for this revision.

The already implemented private jobs and their evidence remain for V2; further
development of jobs/ratings/reviews before V1 stops. This edit concerns plans,
not removal of production code, user history, or existing tests. General
regressions and security checks of shipped code remain in force. The move is an
explicit scope change, not a GREEN, skip, or fixing an old RED. Tests before
every new module, backend/frontend regressions, and end-to-end acceptance of
the current V1 remain mandatory.
